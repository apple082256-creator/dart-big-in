## 1. 공통 사전 조치

1. 서비스와 동기화 작업을 멈춘다(앱, `sync_*_to_mysql.py`, 파이프라인).
2. 운영 파일을 여는 프로세스가 없는지 확인한다.
   ```bash
   fuser db/financial/financial.db db/vector/filings_bge_m3.db db/vector/filings_bge_m3.faiss || echo "no open handles"
   ```
3. 백업 해시를 확인한다.
   ```bash
   (cd backups/local/20261011_pre_2026q1h1_v14 && sha256sum -c SHA256SUMS)
   (cd backups/mysql/20261011_pre_2026q1h1_v14 && sha256sum -c SHA256SUMS)
   ```
4. 롤백 직전 운영 파일도 따로 보존한다(롤백을 다시 되돌릴 수 있게).
   ```bash
   mkdir -p backups/local/20261011_v14_before_rollback
   cp --preserve=all db/financial/financial.db db/vector/filings_bge_m3.db db/vector/filings_bge_m3.faiss \
      backups/local/20261011_v14_before_rollback/
   ```

## 5. MySQL version rollback

v14 동기화는 기존 행의 `data_version`을 v14로 다시 쓰고 2026 행을 활성화했다. 그래서 **current 플래그만 v12로 돌리는 것으로는
충분하지 않다**(2026 행이 활성으로 남고, 로컬 해시와 맞지 않는다). 전체 덤프로 복원한다.

```bash
.venv/bin/python - <<'EOF'
import sys; sys.path.insert(0, "infra/mysql")
from pathlib import Path
from sync_sqlite_to_mysql import MySQL
db = MySQL()
try:
    db.run_file(Path("backups/mysql/20261011_pre_2026q1h1_v14/dart_big_in_pre_2026q1h1_v14.sql"))
finally:
    db.close()
EOF
```

- 덤프는 테이블 23개(`DROP TABLE IF EXISTS` 포함)와 VIEW `standardized_financials`(DEFINER `dart_etl`)를 포함한다.
- `dart_etl` 계정에 `DROP, CREATE, CREATE VIEW` 권한이 있어 같은 계정으로 복원할 수 있다.
- 4.9GB라 수 분이 걸린다. 복원 중에는 백엔드 조회를 막는다.

## 6. current flag 복원

덤프에는 승격 전 플래그가 들어 있어 복원만으로 되돌아간다. 복원 후 다음을 확인한다.

```sql
SELECT data_version, validated, is_current FROM data_versions WHERE is_current = 1;
-- 기대: 2026-10-10-healthcare-rnd-v12, 1, 1  (정확히 1행)
SELECT index_version, is_current, faiss_ntotal FROM embedding_metadata WHERE is_current = 1;
-- 기대: bge-m3-2026-10-09-dart25-h1h3-v11, 1, 147720  (정확히 1행)
```

덤프 복원이 불가능하고 플래그만 임시로 되돌려야 하는 경우(권장하지 않음):

```sql
START TRANSACTION;
UPDATE data_versions SET is_current = (data_version = '2026-10-10-healthcare-rnd-v12');
UPDATE embedding_metadata SET is_current = (index_version = 'bge-m3-2026-10-09-dart25-h1h3-v11');
COMMIT;
```

이 경우 2026 행은 활성으로 남으므로, 로컬 롤백 후 `sync_sqlite_to_mysql.py --data-version <새 버전명>`으로 v12 기준 데이터를
다시 동기화해 2026 행을 `is_active=0`으로 만들어야 한다(축소 감지가 걸리므로 `--allow-shrink` 필요).
