# 계정 표준화 비교: 우리 24개와 팀원 6개

## 결론

팀원 6개 대표 account_id는 모두 우리 24개 핵심 표준계정 안에 같은 ID와 같은 경제적 의미로 포함됩니다. 따라서 6개 모두 `EXACT_MATCH`이며 의미만 같고 ID가 다른 `SEMANTIC_MATCH`는 0개입니다. 현재 대상 5개 기업에서는 여섯 대표 ID가 모두 직접 존재해 대표 ID 하나만 사용해도 기업 단위 누락은 없습니다. 다만 우리 방식은 계정명 변형, IS/CIS 차이, 기간 성격과 검토 상태까지 보존하고 분석 범위를 18개 계정 더 넓혔습니다.

## 1. 팀원 6개 방식

매출액·영업이익·영업활동현금흐름·현금및현금성자산·재고자산·유형자산을 대표 ID 하나씩으로 고정해 빠르게 조회하는 최소형 방식입니다. 구조가 단순하고 여섯 지표 조회에는 효율적입니다.

## 2. 우리 24개 방식

실제 5개 기업의 account_id, 원본 계정명, sj_div, fs_div, 보고서 유형과 검토 상태를 함께 관리합니다. 수익성·재무상태·현금흐름·투자·운전자본 분석에 필요한 24개 표준계정으로 범위를 확장했습니다.

## 3. 동일하게 잡힌 계정

| 개념 | 팀원 대표 ID | 판정 | 팀원 ID 5개 기업 커버리지 | 우리 커버리지 |
|---|---|---|---:|---:|
| 매출액 | ifrs-full_Revenue | EXACT_MATCH | 5/5 | 5/5 |
| 영업이익 | dart_OperatingIncomeLoss | EXACT_MATCH | 5/5 | 5/5 |
| 영업활동현금흐름 | ifrs-full_CashFlowsFromUsedInOperatingActivities | EXACT_MATCH | 5/5 | 5/5 |
| 유형자산 | ifrs-full_PropertyPlantAndEquipment | EXACT_MATCH | 5/5 | 5/5 |
| 재고자산 | ifrs-full_Inventories | EXACT_MATCH | 5/5 | 5/5 |
| 현금및현금성자산 | ifrs-full_CashAndCashEquivalents | EXACT_MATCH | 5/5 | 5/5 |

## 4. 의미는 같지만 ID가 다른 계정

이번 6개 비교에서는 없습니다. 여섯 대표 ID가 모두 우리 핵심 매핑에도 동일하게 포함됩니다. 재고자산은 우리 매핑이 `ifrs-full_InventoriesTotal`도 보조 ID로 허용하지만, 대표 ID `ifrs-full_Inventories` 자체가 5개 기업 모두에 존재하므로 판정은 EXACT_MATCH입니다.

## 5. 대표 ID 하나만 사용했을 때 누락되는 사례

현재 5개 기업과 2023~2025년 수집 데이터의 기업 단위 집계에서는 여섯 ID 모두 5/5이므로 누락 기업은 없습니다. 다만 원본 계정명은 매출액·수익(매출액)·영업수익처럼 달라지고, 영업이익은 IS와 CIS에 나타납니다. 우리 방식은 이런 표현과 재무제표 구분을 함께 보존합니다. 이 결과를 다른 기업 전체로 일반화해서는 안 됩니다.

## 6. 우리 쪽에 추가된 18개 계정

- 현금창출력·비현금비용: 감가상각비
- 수익성: 당기순이익, 매출원가, 매출총이익, 법인세비용차감전순이익
- 운전자본: 매출채권
- 투자·자산구조: 무형자산
- 투자·현금흐름: 무형자산취득, 유형자산취득(CAPEX)
- 재무안정성: 부채총계, 자본총계
- 성장투자: 연구개발비
- 유동성·재무안정성: 유동부채, 유동자산
- 자본·재무안정성: 이익잉여금
- 규모·재무상태: 자산총계
- 현금흐름: 재무활동현금흐름, 투자활동현금흐름

## 7. 왜 24개로 확장했는가

여섯 계정만으로는 최종 순이익, 총자산·부채·자본, 단기 유동성, 매출채권, 투자·재무 현금흐름, 연구개발과 실제 CAPEX를 함께 설명하기 어렵습니다. dart_beginner는 숫자 조회뿐 아니라 기업 간 수익성·재무구조·현금창출·투자 강도를 연결해 분석하므로 18개 계정을 추가했습니다.

## 8. PPE와 CAPEX 구분

| 항목 | 유형자산(PPE) | 유형자산취득(CAPEX) |
|---|---|---|
| 대표 의미 | 보고기간 말 유형자산 잔액 | 보고기간 중 유형자산 취득 현금유출 |
| 재무제표 | BS | CF |
| 기간 성격 | point_in_time | quarterly·cumulative·annual flow |
| 대표 ID | ifrs-full_PropertyPlantAndEquipment | ifrs-full_PurchaseOfPropertyPlantAndEquipmentClassifiedAsInvestingActivities 또는 승인된 세부 계정 합산 |
| 팀원 6개 포함 | 포함 | 미포함 |

PPE가 크다는 사실과 해당 기간 CAPEX가 크다는 사실은 같은 뜻이 아닙니다. PPE는 누적 잔액이고 CAPEX는 기간 중 현금 지출입니다.

## 9. 두 방식의 장단점과 적합한 목적

- 팀원 6개 방식은 구현이 단순하고 핵심 지표를 빠르게 조회하기 좋습니다. 현재 5개 기업에서는 직접 ID 커버리지도 5/5입니다. 다만 범위가 여섯 지표로 제한되고 계정명·제표구분·기간 의미의 예외 관리가 적습니다.
- 우리 24개 방식은 더 많은 분석 질문에 대응하고 기업별 표현 차이와 direct·derived CAPEX를 추적할 수 있습니다. 대신 매핑·검증 구조가 더 복잡하고 사람이 검토해야 하는 후보가 생깁니다.
- 단순한 핵심 지표 조회에는 팀원 방식이 적합하고, 다기업 비교와 Financial DB·Vector DB 통합 분석에는 우리 방식이 적합합니다.

## 발표용 요약

팀원 기준은 핵심 6개 재무계정을 대표 account_id 하나씩으로 고정한 최소형 표준화 방식입니다. 실제 5개 기업 데이터에서 여섯 ID는 모두 직접 존재하며 우리 24개 표준계정에도 같은 ID와 의미로 포함됩니다. 따라서 이번 범위에서는 6개 모두 EXACT_MATCH이고 대표 ID 때문에 누락되는 기업은 없습니다. 우리 방식은 계정명과 IS/CIS 차이, 기간 의미, 검토 상태를 함께 관리하고 수익성·재무상태·현금흐름·투자·운전자본 계정을 추가했습니다. 특히 PPE는 시점 잔액이고 CAPEX는 기간 현금유출이므로 서로 다른 표준계정으로 유지합니다. 팀원 방식은 빠른 핵심 조회에, 우리 방식은 다기업 비교와 근거 추적이 필요한 서비스 분석에 더 적합합니다.
